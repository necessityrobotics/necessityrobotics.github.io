In plain words

This page is for engineers. It describes xclean, our robot software.

xclean tells a robot where it is, and where it has been, while it moves. It needs a camera with two eyes (a stereo camera) and a computer with an NVIDIA graphics card. A motion sensor (IMU) is optional. It needs no satellite signal.

Free for anyone. Walk through 8 real places that it helped to rebuild in 3-D.

xclean

Real-time stereo visual-inertial SLAM, built in India. Python, with GPU code in CuPy and CPU hot paths in Numba: no C++ build step, no ROS. Connect any calibrated stereo rig (two cameras side by side, pinhole lenses, both images taken at the same time), with or without an IMU, live or from a recording. Live sources through xclean live --source: the Luxonis OAK-D-Lite (built in), a USB stereo camera, two USB cameras (not synchronised: only for tests with a still or slow rig) or your own source for any camera SDK. We tested live runs only on the OAK-D-Lite; the other sources with recordings and simulated cameras. It runs on Windows 11; from version 0.2.0 it also installs on Linux and NVIDIA Jetson Orin and Thor.

What it does

xclean estimates the pose of a stereo camera at every frame, while it moves. When tracking works, each published pose comes from a solve that contains that frame. When tracking fails, xclean publishes a predicted pose and marks it "coasting". Loop corrections are applied live.

xclean is a stereo visual-inertial SLAM system: it uses the IMU while a built-in consistency check accepts it, and otherwise continues as stereo visual odometry with loop closure. In the final board the IMU stayed in use to the end on 50 of 216 runs (mostly EuRoC and 4Seasons). On MADMAX, Rosario and our own OAK-D-Lite recordings the check dropped or refused it. KITTI has no IMU. Per dataset.

  • On the GPU: feature detection, ORB descriptors, stereo matching, and the first feature-matching step of each frame.
  • Inertial, on the CPU: IMU preintegration, with an online consistency check that can drop or refuse the IMU. xclean does not estimate the camera-IMU time offset: if you know it, add it to the camera time stamps.
  • Back end on the CPU (Numba): matching against the local map, and the sliding-window factor graph that gives each frame its pose.
  • Full SLAM: loop closure, relocalisation and map reuse, in a separate CPU process outside the frame path; their corrections are applied to the published pose live.
  • No learned networks in the SLAM pipeline.

"Written in CuPy" does not mean "pure Python": CuPy compiles our CUDA C source at first use (NVRTC), and the CPU hot paths are compiled by Numba.

Install and run

Install and run instructions will be published with the code.Download xclean 0.3.0 (source code, zip, about 1.3 MB), or clone it: git clone https://github.com/necessityrobotics/xclean. Install and run instructions are in its README. Any stereo rig, live: the guide. What you will need: a calibrated stereo camera or a recorded sequence (for live mode: a calibrated stereo rig; the OAK-D-Lite is the only camera we tested live); Windows 11 (64-bit) or Linux (x86-64 or ARM64); an NVIDIA GPU of the Turing generation (RTX 20 series) or newer, with a driver that supports CUDA 13 (R580 or newer); conda; and git. No CUDA Toolkit is needed: the conda environment carries the CUDA kernel compiler. On an NVIDIA Jetson, use JetPack 7 (Jetson Thor, or Orin on JetPack 7.2) or JetPack 6 (Jetson Orin, CUDA 12.6) with a Python venv.: see the Linux and Jetson guide.

Known limits

Tested on one machine: AMD Ryzen 9 9950X, NVIDIA RTX 5090, Windows 11. Other CPUs, GPUs and drivers are not tested. Linux and Jetson (version 0.2.0): every install route installs and passes the unit tests on GitHub's Linux machines (x86-64 and ARM64, no GPU), and every GPU kernel compiles for Jetson Orin and Thor, but we have not run xclean on a Linux GPU or a Jetson, so its accuracy and speed there are unmeasured. macOS has no CUDA. At start-up the GPU front end checks itself against the CPU code. If only its 3×3 solver differs (expected on CPUs without AVX-512), xclean prints a note and keeps the GPU front end. If another check fails, xclean says so and runs the whole route on the CPU front end, with higher latency.
